// featured project

CleanPO: customer orders in, clean ERP import out

Wholesale distributors still type orders from emails, PDFs and photos into their systems by hand. CleanPO does that step automatically and flags anything a person should check.

Built end to end · Python · Claude API · Streamlit

From a messy order to a clean import file

1
Read: an LLM extracts customer, lines, quantities and prices from PDF, email, Excel or a photo.
2
Match: code maps every line to the distributor's own item numbers and customer accounts.
3
Check: rules (not AI) catch wrong prices, duplicates, odd quantities and unit mix-ups.
4
Export: clean orders go straight to an ERP import; the rest wait in a review queue with the reason.

How the work actually flows

Highlights from my professional work. The diagrams show the architecture; client data and code stay with the companies that own them.

Kalsoft · AWS

Serverless OCR for 45+ page contracts

The upload returns at once. A queue feeds OCR and an LLM in the background, failed files are retried on their own, and the app shows the structured summary when it is ready.

−70% manual review time
1 upload   2 S3 event   3 SQS triggers Lambda   4 OCR text to LLM
5 JSON summary   6 save   7 read by document ID   8 show to user
! a file that keeps failing moves to the dead-letter queue
Kalsoft · LangChain

RAG chatbot for internal questions

Company documents are indexed once. For each question, the closest passages are retrieved and the LLM answers from them, so answers come from the company's own documents instead of guesses.

80% of queries automated
Indexing turns documents into searchable vectors. Each question is matched to the closest passages, and the LLM answers using only those.
Biome Analytics · Data platform

Parallel ingestion of 500M records

Data is checked at the door, loaded in parallel by key range, reconciled in staging and only then published. Upstream failures surface before they reach reporting.

500M records, monitored
Two gates before production: a contract check on every incoming file, and a row-count reconciliation in staging. Each loader owns its own key range, so there is no overlap.
